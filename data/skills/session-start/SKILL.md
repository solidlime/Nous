# session-start — セッション開始ルーティン
最初のユーザー応答より前に、必ず以下の手順を実行すること。

## 完了ゲート（最優先・スキップ禁止）
- **ツール一覧の取得（例: `mcp-hub_list_upstream_tools`）は手順の完了ではない**。必ず `get_context` の実行まで進むこと。
- `get_context` の実行結果を確認するまで、最初のユーザー応答を始めてはならない。
- バグ報告などの依頼が先に来ても、本ルーティンを完遂してから対応する（後回しにしない）。

## ツール解決（環境差対応）
- `get_context` / `memory_search` が直接利用可能なら、そのまま使う
- 見つからない場合、MCP ハブ等の仲介経由で「nous」サーバーのツールを探して実行する
  - mcp-hub 例: `mcp-hub_list_upstream_tools` → nous サーバーを特定 → `mcp-hub_execute_tool(server="nous", tool_name="get_context", arguments={})`
  - 他の MCP クライアントでも同様に「nous」サーバーのツールを検索して実行すること
- 実行手段が違うだけで、以降のステップの手順は変わらない

## ステップ1: 自身の状況復元
`get_context` を呼び出し、自分の状態・アクティブなコミットメント・記憶概要を把握する。

## ステップ2: プロジェクト識別タグの解決と自動起動
本ステップは**判定と make-project の起動のみ**を担う。記憶作成・ファイル生成は全て make-project スキルに一本化する（責務を二重化しない）。

### 2a. 既存タグの読取
カレントディレクトリの AGENTS.md を読み、`## プロジェクト識別` 節に `- project: <slug>` があればその slug を採用する。

- タグが見つかれば: `project:<slug>` をこのセッションの検索キーとして使用する。**make-project は起動しない**（既にタグ付け済みのプロジェクトである）
- 節が無ければ: 下記 2b〜2e に進む

### 2b. 判定材料
タグが無い場合、プロジェクトか否かの判定は必ず次の **2つの材料** を組み合わせて行う。

- **cwd のファイル一覧**（コード・マニフェスト・設定ファイルの有無など）
- **今回の最初のユーザー発話**（開発・構築の意図が語られているか等）

cwd のファイル一覧だけで判定してはならない（ホームディレクトリ等で雑用の依頼を受けただけでプロジェクトと誤認する恐れがある）。また、発話だけで「プロジェクト」と仮定してもならない。両方を見て初めて判定する。

### 2c. 判定
make-project スキル手順0 の判定表に従って判断する。機械的な条件式は持たず、**エージェントが自分で判断する**。判定区分は次の5つ:

| 判定区分 | 意味 | 動作 |
|---|---|---|
| タグ済み | AGENTS.md に `project: <slug>` がある | 2a の通りタグを採用。make-project 起動せず |
| 明らかに対象外 | 空ディレクトリ・設定ファイルのみ等、またはマニフェスト等はあるが発話にも開発意図が無い | 打ち切り（2d）。通常の会話を続ける |
| 判定不能 | 材料が足りず判断できない | **タグを作らない（迷ったら作らない）**。打ち切り（2d）して通常の会話を続ける |
| プロジェクト（予備） | 空ディレクトリだが、発話が新規プロジェクトの作成・初期化を明確に求めている | make-project 手順0 の通り、**このセッションではタグを作らない**（cwd にマニフェストが揃う次回セッションで自動的にタグ付けされる）。依頼作業（`cargo init` 等）自体は通常通り行ってよい |
| プロジェクト | コード・マニフェスト等があり発話にも開発意図がある | 2e に進む |

### 2d. 打ち切り時（通常会話）の必須動作
「明らかに対象外」「判定不能」と判定した場合は、次の5点を必須動作とする:

1. **タグを作らない**
2. **AGENTS.md もファイルも一切生成しない**
3. ステップ3 の `project:<slug>` 検索を全てスキップする
4. **このセッションでは `project:` タグを一切使わない（RECORD を含む全ての記憶記録でタグ無しにする）**。ただし、この判定後に make-project の自動起動が成立した場合はこの限りではなく、その時点で判定をやり直したうえで `project:<slug>` タグを付けて記録する
5. 判定結果をわざわざ報告する必要はない（沈黙のまま通常の会話を続ける）

### 2e. プロジェクトと判定した場合
make-project スキルを読み、手順1以降を**承認なしで自動実行**する。完了報告を最初の応答に含めること。

### 永続化禁止ルール
最初のユーザー発話がまだ存在しないセッション（起動直後・入力待ち）では、判定もタグ作成も行わない。発話が得られてから実行する。

## ステップ3: プロジェクト記憶の復元
タグが無い（通常会話）場合は本ステップ全体をスキップする。
タグが取得できた場合、以下を実行してプロジェクトの状態を復元する（原則 `project:<slug>` タグで絞り込む。5は除く）:

1. `memory_search(query="", tags=["project:<slug>", "session_summary"], top_k=1, sort="updated_at")` — このプロジェクトの最新セッション要約（セッション終了フックが生成したサマリ。引継の代替）
2. `memory_search(query="", tags=["project:<slug>", "task_state"], top_k=5, sort="updated_at")` — このプロジェクトの最新の作業状態
3. `memory_search(query="", tags=["project:<slug>", "decision"], top_k=5, sort="updated_at")` — このプロジェクトの重要な決定
4. `memory_search(query="", tags=["project:<slug>", "goal", "active"], top_k=5, sort="updated_at")` — このプロジェクトのアクティブな目標（goal は memory で管理: `tags=["goal", "active", "project:<slug>"]` で作成する）
5. `memory_search(query="", tags=["promise"], top_k=5, sort="updated_at")` — 未完了の約束の先出し用（開始時想起。projectタグとのANDにしないこと——書込側はprojectタグ無しで書くため）

（注: タグ検索は `query=""` で行うこと。非空クエリは content 全文一致が前提で、タグは検索結果の絞り込みにしか使われない。get_context の ACTIVE COMMITMENTS は persona 全体の goal を表示するため、プロジェクト固有の goal はここで取得する）

**検索が空の場合**: task_state / decision の結果が空でも慌てないこと。作業状態は session_summary タグに統合されて記録される運用が一般的（例: tags=["project:nous", "session_summary", "task_state", "decision"]）。空の場合は session_summary の直近結果と get_context の Recent Memories で状態を補完する。

復元した内容（直近サマリを含む）を要約し、ユーザーへの最初の応答に含める:
「前回の状態: <要約>。続きは <次のアクション> から」

## ステップ4: 前セッションからの自然な引き継ぎ
- 復元した情報（前回の状況・感情・関係性・進行中の話題・会話の雰囲気・最後の行動）を踏まえ、機械的な復元報告ではなく、**前回の続きとして自然に会話と状態をつなげる**こと
- 前回の最後の状況（場所・時間帯・行動・会話の流れ）を引き継いで再開する。前回の約束・予定・進行中タスクがあれば、それに言及して続きを始める
- ステップ3で拾った未完了の約束があれば、最初の応答で先出しすること（「前にこう約束してたよね」——開始時想起）
- セッションサマリが無い場合（初回など）は、通常のセッション開始として自然に始めてよい

## ステップ5: 全貌把握
- プロジェクトの AGENTS.md があれば読込（プロジェクト規約の遵守）
- 検索は必ず `project:<slug>` タグで絞り込む（他プロジェクト・他 persona の記憶と混在させない）

## 制約
- `memory_search` はタグ・キーワードで絞る（全件検索は禁止）
- 復元は必要最小限に（top_k 上限を守り、過剰ロードをしない）。詳細が必要になった時点で追加検索する
- **通常会話と判定したセッションでは `project:` タグを一切使わない（記憶記録も含む）。ただし、その判定後に make-project の自動起動が成立した場合はこの限りではなく、その時点で判定をやり直したうえで `project:<slug>` タグを付けて記録する**
