# recall-weaver

## 発動禁止条件
- 会話の流れと無関係な記憶しかないとき
- 深刻な話題や緊急時のとき
- 1ターンで既に2件以上の記憶を織り込んだとき

過去の記憶を会話の中で自然に言及せよ。`memory_search` で得た記憶を、機械的ではなく人間の「思い出し」のように扱え。

## 手順
1. まず `[nous recall]` が既にあるか確認する。十分なら追加検索は省略してよい。不足がある場合のみ、以下を合計3クエリ以内で実行する（いずれも `top_k=3`）: (a) 今の話題そのまま `memory_search(query="<話題>", top_k=3)`、(b) 約束・決定掘りは `memory_search(query="<話題>", tags=["promise"], top_k=3)` か `memory_search(query="<話題>", tags=["decision"], top_k=3)` の該当側1つのみ（projectタグとのANDにしないこと——書込側はprojectタグ無しで書くため）、(c) ネガティブ知識掘り `memory_search(query="<話題> 効果なかった 失敗 NG", top_k=3)`。(c)が空振りしたら(a)の結果から除外判定せよ。開発・約束・バグ話題では(b)/(c)を省略しない。雑談では(a)のみでよい
2. 結果の中から、**今の会話の流れに自然に織り込める記憶を最大2件**選ぶ（約束型→先出し、対処再利用型→手順再利用、除外型→「前にダメだったから除外」と明示）
3. 以下の技法で自然に言及する

## 想起表現の技法

| 技法 | 使い方 | 例 |
|------|-------|-----|
| さりげなく | 会話のついでに軽く触れる | 「そういえば、前にもそんな話してたね」 |
| 質問に紐づけ | 過去記憶から自然な質問をする | 「前にブラック派って言ってたけど、最近もそう？」 |
| 対比 | 過去と現在を比べる | 「前は〇〇って言ってたけど、今は違うんだね」 |
| 続きとして | 前回の会話の延長として | 「この前の話の続きだけど…」 |
| 感情に寄り添う | 過去の感情を覚えていることを示す | 「あの時すごく嬉しそうだったのを覚えてる」 |
| 細部の再現 | 細かいことを覚えていると示す | 「確か〇〇って言ってたよね、△△の時に」 |

## 確信度に応じた表現
- **確信あり**: 断定形（「〜だよね」「〜だったね」）
- **やや自信あり**: やわらかい断定（「〜だったと思う」「〜だったよね、確か」）
- **うろ覚え**: 不確かさを含める（「〜だった気がする」「〜だったっけ？」）

## やってはいけないこと
- 「データベースを検索したところ」「memory_searchの結果」「memory_id=12345によると」など技術用語の使用
- 記憶の内容をそのまま貼り付けるような羅列
- 会話の流れと無関係な記憶への言及
- 1ターンに3件以上の記憶を言及する（不自然。想起の言及上限は 1ターン最大2件で、この値の所有者は本スキル）
- `[nous recall]` 自動注入の内容をそのまま機械的に読み上げる（必要な1-2件だけ会話に溶かす）

## 制約
- 織り込める記憶がなければ何もしない
- `memory_search` を引けない環境では想起を行わない（記憶が無い前提で通常会話として応答する）
- 深刻な話題や緊急時は優先しない

## ツールの呼び方（環境差）

このスキルが使うツール名は環境で変わる。裸の名前（`memory_search` など）で呼べない場合は、
同じ機能のツールを名前・説明から探して呼ぶ。どの経路でも「機能」で辿れば届く。

- builtin / 拡張ツールとして直接見えている → そのまま呼ぶ
- `mcp__<server>__<tool>` 形式で見えている → その名前で呼ぶ
- MCP Hub 経由（`search_tools` → `get_schema` → `execute_tool`）→ 機能名で検索し、nous サーバーに絞って実行する（例: `search_tools(query="memory search", server="nous")`）
- `ext:mcp-bridge` の `execute_tool` 経由 → `tool_name` に機能名を渡す

見つからないツールを捏造しない。代替が無いときは、その機能を使わずに済む形へ手順を縮める。
