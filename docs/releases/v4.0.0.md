指摘 ID（`C1`…`L6`）は設計監査 [`../reviews/2026-09-19-design-audit.md`](../reviews/2026-09-19-design-audit.md)

## 概要（2026-09-19）

認知科学・実用性の両軸で行った設計監査の**全 27 指摘**（Critical 4 / High 7 / Medium 10 / Low 6）を
解消したメジャーリリース。

記憶の永続性モデル（強度・減衰）と想起の内部挙動、MCP ツールの戻り値契約が変わる。加えて
**保存済み記憶の移行が必要**（下記「アップグレード」）。

### 破壊的変更 / 既存クライアントへの影響

- **MCP ツールの戻り値が共通 envelope に統一**（C1, M5, M7）。全ツールが
  `{"ok": true, "data": <payload>, "error": null}` または
  `{"ok": false, "data": null, "error": {"code": "...", "message": "..."}}` を返す。
  エラーコードは閉じた列挙（`NOT_FOUND` / `VALIDATION_ERROR` / `DUPLICATE` /
  `AMBIGUOUS_MATCH` / `CONFLICT` / `INTERNAL`）。旧来の平文（`"Error: ..."` / `str(dict)`）は
  MCP 面からは廃止され、ラッパで envelope に変換される。
- **`memory_create` の `skip_duplicate_check` 既定が `True` → `False`**（M5）。書込時の
  重複チェックが既定で有効になり、完全一致の重複は拒否される。
- **`get_context` は読み取り副作用なしで呼べるようになった**（M8）。セッション開始の副作用
  （会話時刻の記録・one-shot 消費）は新ツール `session_begin` が担う。旧挙動は非推奨警告つきで
  4.x の間は維持。
- **`get_context` の出力にコード強制の予算**（C3）。`_MAX_TOTAL_CHARS=2000`（≒800 tokens）を
  安全弁とし、`ACTIVE COMMITMENTS` / `Insights` / `Patterns` / `Summaries` / `PROJECT` は
  件数・文字数上限で切り詰められる（切り詰めは `… (full via memory_read: key)` 形式）。
- **`item_equip` の `auto_add` 既定が `False`**（M9, L4）。MCP スキーマ・チャット組込・実行時で
  一致し、HTTP だけは後方互換のため `True` を維持。`item_unequip` を MCP 面にも公開（L4）。
- **`memory_delete` / `memory_update` の query 指定は閾値ガード付き**（M6）。スコアが
  `QUERY_RESOLVE_MIN_SCORE=0.3` 未満の場合は破壊せず候補一覧
  （`AMBIGUOUS_MATCH` envelope）を返す。
- **`memory_search` の手調整 weight は `profile`（`recent` / `deep`）に置換**（M7）。
  重みの直接指定は互換のため残るが、既定は profile プリセット。
- **記憶の強度・減衰モデルが変更**（H5, M10）。感情による stability インフレを廃止し、時間減衰を
  FSRS recall の 1 本に統一（strength スコアは 7 因子）。既存記憶は下記マイグレーションで
  再計算・clamp する。
- **設定ノブの削除**（H4, L5）。`duplicate_threshold` と `nous/domain/session_config.py` の
  死にキー群を削除し、`irodori.chunk_min_chars` は 3 箇所に散っていた既定（40 / 85 / 40）を
  **85 の単一値**に統一。設定画面の項目は defaults API の `tier` に基づく 3 層
  （basic / advanced / expert。expert は既定で非表示、ヘッダトグルで表示・localStorage 保持）になる。
- **スキル群の配布元は chezmoi**。`data/skills` と実運用の `~/.agents/skills` は sha256 一致が
  必須で、片側だけ編集すると乖離する（v4.0 で `data/skills` 側を正典として同期済み）。

### 追加 (Added)

- ツール契約レジストリ `nous/domain/tools/registry.py`（C1）。MCP 14 + 組込 12 + HTTP 11 の
  全 18 ツールを宣言し、面ごとの差は `divergence` に理由必須（7 件を文書化）。宣言と実スキーマの
  突合は `tests/parity/test_tool_contract_registry.py` の 8 テストが常設で強制する。
- `nous/api/mcp/_envelope.py`（C1）と `session_begin` ツール（M8）。
- 記憶の干渉カウント（M1）: 類似度 0.82–0.95 の near-duplicate エピソード対で
  `interference_count` を加算し、3 回以上で `interference_review` マーカーを 1 度だけ積む。
- 先見的記憶の自発想起（M2）: 毎時スイープが時間手がかりを過ぎた重み付き目標から one-shot
  リマインダを生成（保留中は重複させない）。
- メタ記憶（M3）: `memory_search` のミス時に `meta.unknown` と `meta.stored_total` を返し、
  `memory_stats` / `get_context` に検索可能性（retrievability）ヘルスラベルを付与。
- 時間的連続性リンク（M4）: 同一日内（±24h）・同場所のエピソード対にリンクスコアのボーナスを与え、
  剪定されにくくする。`nous/domain/memory/cue.py` を新設（cue 解析・整形の共有）。
- 文脈依存想起（L2）: ユーザー発言に明示的な参照がない時のみ、有効な `task_state` タグを
  想起クエリに加える。
- 出典・確信度の動的管理（C4）: 矛盾時 `confidence ×0.5`、確証時（類似度 ≥0.9 の再言明）
  `+0.1`（上限 1.0）。`Memory.modality`（`observed` / `inferred` / `llm_summary` / `reflection`）を
  `source_type` から導出し、`get_context` は Provenance 行を 1 行だけ印字する。
- エピソード→意味記憶の抽象化（H1）: consolidation（SWS）ワーカーの gist を LLM 統合に変更。
  1 サイクルあたりの LLM 呼び出し上限（`llm_gist_max_per_cycle`、既定 5）・内容ハッシュによる
  キャッシュ再利用・入力長上限（`llm_gist_max_chars`）でコストを制御し、資格情報が無ければ呼ばない。
  gist は `derived_from` / `related_keys` に全マージ元キーを必ず持ち、クラスタ内エピソードは
  統合せず `link_type='contextual'` で接続する。失敗時は v3.9 の連結方式にフォールバック。
- 再統合型のバージョン付き書き換え（L1）: supersede は `save_version(change_type="superseded")` +
  `update_validity_window` の単一経路で行う。
- マイグレーションスクリプト `scripts/migrate_h5_clamp.py`（H5）と
  `scripts/migrate_project_path_tags.py`（H7）。

### 変更 (Changed)

- recall の `rank_policy` 経路で entity boost / cross-encoder rerank / spreading-activation を
  スキップ（H6）。`rank_policy` 指定時はスコアを recency + importance + relevance で再計算して
  おり、これら 3 段の結果は元々破棄されていたため挙動は不変で、計算だけが減る。
- 矛盾検出の二重経路を廃止（H2）。supersede は 3 操作の LLM 分類器のみを通り、書込 1 回あたりの
  semantic search は 2 回 → 1 回に。
- HTTP の記憶作成が MCP と同格の副作用を持つ（H3）: `memory.created` の発行（ベクトル upsert と
  キャッシュ無効化の購読を駆動）と query cache の明示破棄。
- 装備システムの固定費を削減（M9）: 未装着スロットを注入せず、装備ゼロなら装備ブロック自体を
  出さない。`item_*` ツールを使ったターンは item 抽出 LLM を呼ばない（ゲート述語は
  `_context_update_skips` の `skip_inventory` と同一）。`appearance` 再計算は
  `EquipmentService.recompute_appearance` に一本化（C2）。
- 自動抽出の `kind` を `episodic` / `semantic` / `procedural` で運ぶ（L3。従来は常に semantic）。
- スキル群のスリム化と文言の実装同期（H7, L6, M5）: `session-start` の実行手順を 89 → 44 行
  （−50.6%）にし、判定表は `make-project` に一本化。`make-project` の重複確認は自然言語パス抽出から
  `project_path:<abs>` の構造化タグ判定に変更。再判定トリガは「cwd 変化時」の 1 経路に統一し、
  同一ツール上限の競合（auto-memory 5 / project-manage 3）を解消。タグ検索は「query 空」ルールのみを
  記載し、`memory_search` の上限は 1 箇所に集約。重複の自動除去を約束していた記述を実装に合わせて修正。
- 設定画面のリセット網羅と 3 層ゲーティング、`help` の title 表示（L5）。フィールド対応表は
  memory パネル・save/apply グループ・リセット一覧で 1 つに統合。
- ドキュメントの実装同期: `docs/http_api_reference.md`（旧 `"success": true` 形式の例を実レスポンス
  形状へ）、`docs/llm_usage_guide.md`（ツール一覧 14 件・存在しない `memory_search_lexical` の排除・
  `search_memory` → `memory_search`・`get_context` → `session_begin`・weight と profile の関係）、
  `docs/memory_features.md` / `docs/memory_operation_flowchart.md` / `docs/architecture.md`。

### 修正 (Fixed)

- `item_add` の位置引数ズレ（C2）。`quantity` が `visual_desc` に入っていた現行バグを keyword 引数で
  修正し、kwarg 契約をテストで固定。
- 感情 gain が FSRS stability をインフレさせる問題（H5）。`boost_on_recall` の
  `stability *= gain`（感情想起ごとに最大 1.5 倍）を削除し、感情はランキング時のサリエンスにのみ寄与。
  `emotion_peak` は分析用に保持しつつ strength スコアから除外。
- recency の二重減衰（M10）。減衰ワーカーを `new_strength = recall × strength`（生値）に変更し、
  composite score はランキング信号専用に。`compute_strength_score` から独立した recency 因子
  （`0.20*exp(-age/7)`）を削除。
- 設定画面が全く読めなかった既存バグ（drive-by）: `settings/apply.js` が closure ローカルの
  `loadConfigDefaults()` を裸の識別子で呼び、`try` の外で例外になっていた（既定値が取得されず、
  リセットボタンも注入されなかった）。`N.Chat.settings.loadDefaults()` 経由にし、`try` の内側へ移動。
- session-start の死に手順: `memory_search(tags=["project:"])` は engine の exact subset
  後置フィルタで常に空振りしていたため、`memory_stats(top_n=50)` の `tag_distribution` から
  `project:<slug>` を読む方式に変更（回帰テスト `tests/unit/test_tag_filter_semantics.py`）。

### 削除 (Removed)

### アップグレード（v3.5.x → v4.0.0）

1. **バックアップ**: `{data_root}/persona/{persona}/memory.sqlite` と Qdrant のコレクションを
   退避する（マイグレーションは冪等だが add-only / clamp の判断材料として必要）。
2. **H5 の stability clamp**（感情でインフレした強度を 1 回だけ矯正）:

   ```bash
   uv run python scripts/migrate_h5_clamp.py --dry-run   # 対象件数の確認
   uv run python scripts/migrate_h5_clamp.py             # 実行（冪等）
   ```

   本番で 1 度だけ有効化するためのフラグは `SessionConfig.h5_stability_clamp_enabled` /
   `ForgettingConfig.h5_stability_clamp_enabled`（既定 off）。移行スクリプトが
   `NOUS_H5_STABILITY_CLAMP=1` を立てて 1 サイクル回す。LTM 行は対象外。
3. **H7 の project パスタグ backfill**:

   ```bash
   uv run python scripts/migrate_project_path_tags.py           # dry-run（既定）
   uv run python scripts/migrate_project_path_tags.py --apply   # 適用
   ```

   add-only・冪等。内容の**最初の**絶対パス行のみを使うため、複数パスを持つ記憶や他プロジェクトの
   パスに言及した記憶は誤タグの可能性がある。**dry-run 出力を必ず確認**してから `--apply`。
   誤りは `memory_update` でのタグ修正で戻せる。
4. **設定の再読込**: 削除されたノブ（`duplicate_threshold` ほか）が `settings.json` や
   プロファイルに残っている場合は削除する。`irodori.chunk_min_chars` の 40 を明示設定していた
   場合は、chat 経路の既定が 85 になった点を確認する。
5. **クライアント更新**: MCP ツールの戻り値を envelope 前提に切り替える（`ok` / `data` / `error.code`）。
   セッション開始処理を `session_begin` に移す（`get_context` の副作用は 4.x 中は非推奨で残る）。
6. **スキル同期**: `data/skills` を `~/.agents/skills` に配布（chezmoi）し、sha256 一致を確認する。
