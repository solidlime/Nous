# 連想想起スキル誘導 A — Design

Date: 2026-09-03
Status: approved (user: 「いいよ。好き」)
Scope: チャット応答中の連想活用（約束・バグ対処・効果なかった処置）

## 背景・現状

- 記憶の書込は正常 (auto_capture / auto_extract 稼働中)。
- 読取側の課題:
  - `prepare.py:196-204` プリロードは直近3発言結合クエリ × top5固定。
  - entityブースト (+0.1) + SA連想 (`engine.py:403-419`, `min(act*0.2,0.1)`) は生きてるが、RRF+複合スコア (recency 0.3 / importance 0.3 / relevance 0.4 in `memory_retriever.py:48-71`) で薄まる。
  - 深掘りはLLM任意の `memory_search` 頼み (`prompt.py:65-66`)。数値ゲートなし。
  - `get_context` は importance順+タグ直取りの非連想のまま (仕様通り・軽量)。
  - enrich は書込時BGのみ、読取時なし (`session_config.py:65` 既定False)。
- 結果: 同じ間違いの繰り返し・同じ説明の繰り返しが起きる。

参照: exp-1 調査 (entity_repo.py:176, use_cases.py:401, engine.py:350-376/403-419, search.py:22-99)。

## 目的・成功条件

- 目的: 会話中・開発中に過去の約束・バグ対処・効果なかった処置を連想で役立てる。
- 成功条件:
  1. 同じバグ手を二度打たない (ネガティブ知識の除外が効く)。
  2. 同じ説明を三度しない (約束・決定の先出しが効く)。
- 非目的: プリロード重みチューニング (案B)、ルールベース二段検索 (案C)、WebUIグラフ活用。Aで足りないと分かったら追加する (YAGNI)。

## 設計 (案A: スキル誘導型)

### 1. 発動条件

以下3種のいずれかに該当したら確定で想起する。雑談では発動しない。

- 約束・TODO・次回系
- バグ・不具合・エラー・直らない系
- 開発方針・やり方・過去の決定系

### 2. 想起手順

- `memory_search` を最大3クエリ:
  1. 今の話題そのまま (query=text, top_k=3)
  2. 約束・決定タグ絞り (query=text, tags=["promise"] か ["decision"] の該当側1つのみ1クエリ, top_k=3。projectタグとのANDにしないこと——書込側はprojectタグ無しで書くため)
  3. ネガティブ知識掘り (query=text + 効果なかった・失敗・NG, top_k=3)
- 既存の hybrid + entityブースト + SA をそのまま使う。追加インフラなし。
- 1ターンに織り込むのは最大2件まで (recall-weaver制約)。

### 3. 活用手順 (3型)

- 約束型: 「前にこう約束してたよね」で先に提示 → 説明の繰り返し防止。
- 対処再利用型: 「前はこの手で直したよ」と手順再利用。
- 除外型: 「これは前にダメだったから除外ね」と繰り返し防止。
- 想起表現は recall-weaver の技法に従う (さりげなく・対比・続きとして等)。技術用語 (memory_search結果等) を会話に出さない。

### 4. アーキテクチャ・変更点

- 変更はプロンプト + スキル手順のみ。最小diff:
  - `nous/application/chat/pipeline/prompt.py:65-66` の指示を「関連しそうなら呼べ」→「開発・約束・バグ話題では必ず呼べ」に格上げ。
  - `recall-weaver` スキル手順に上記3クエリ手順を追記 (or 別スキル化はしない)。
- `memory_retriever.py` / `engine.py` / `entity_repo.py` は触らない。
- skipped: 案B (重み調整・top_k拡大)、案C (確定二段検索)。add when: A運用で取りこぼしが実測されたら。

### 5. データフロー

```
user発話 → トピック判定 (3種?) → Yes: memory_search×最大3 → 上位2件まで整形 → 応答に織り込み (3型)
                                  → No: 通常応答
```

読取時enrichなし・書込時BGのみの現状は変えない。

### 6. エラーハンドリング・縮退

- 記憶が空でも止まらない。通常応答に縮退。
- 誤想起したら「違ったら言いなさい」で修正受け付け。即再検索しない。
- タイムアウト時はプリロード分だけで応答 (既存の try/except縮退に準拠)。

### 7. テスト・検証

- 会話による目視確認のみで合格とする (堅苦しい契約テストなし):
  - 過去の約束を聞いたら先出しされるか。
  - 過去に失敗した手を言ったら除外されるか。
- 既存スイート緑は維持 (変更がプロンプト・スキル文面のみのため、pytest追加なし)。
