# SPEC - make-project 自動検出拡張

- 日付: 2026-08-14
- 状態: 実装済み（`data/skills/` に反映済み。`~/.agents/skills/` への配布は chezmoi externals が GitHub `main` の archive を取得する経路なので、push 後に `chezmoi apply -R` で反映される）
- 関連: make-project / session-start / SPEC-nous-unification.md

## 背景

新規プロジェクトで「明らかにコーディングプロジェクト」と判断できる場合に、
AGENTS.md の自動生成とプロジェクトタグ（`project:<slug>`）の自動付与を行いたい。

現状:
- make-project は自動検出で動く（cwd のファイル一覧 + 最初のユーザー発話の2つで判定）
- session-start は判定と make-project の自動起動を担い、記憶作成・ファイル生成は make-project に一本化
- nous アプリ自体は不変更方針（配布は chezmoi externals 経由のスキルファイルのみ）
- 自動起動の確実な経路は session-start 2e のみ（make-project の description による能動ロードはハーネス依存で保証されない）
- 初回判定は最初のユーザー発話で1回だけ走るため、会話が発展してコーディングを始めてもタグが付かないことがある。これを塞ぐため再判定トリガー（cwd が変わった時）を導入する
- 再判定トリガーは**cwd の変更のみ**で発動する。**同じ cwd 内で会話がコーディングに発展するケースは対象外**（タグを付けず、再判定も走らない）

## 方針（ユーザーとの合意事項）

1. **トリガー**: session-start ステップ2から make-project にリンクし、セッション開始時に判定を実施。コーディング開始・初期化リクエスト検知時にも make-project が発動する。
2. **判定**: 機械的条件式ではなく LLM（エージェント）がファイル状態と発話を見て判断。
3. **確認**: 判定・slug 決定・重複確認は自動。タグ確定の直前に1問だけ確認を取る。承認後は自動実行・事後報告。拒否・訂正は「変異前の停止」（何も変異させない）。確認後に誤りが判明した場合のみ、生成物と記憶の取り消しを行う。
4. **生成物**: AGENTS.md + `project:<slug>` タグ付き初期記憶（従来の make-project 生成物と同じ）。既存 AGENTS.md は上書き禁止で、`## プロジェクト識別` 節のみ追記可。
5. **スコープ**: make-project スキル + session-start スキル（ステップ2の判定・起動リンク）を変更。nous アプリ / プラグインは変更しない。

## 機能要件

### F1: プロジェクト判定
セッション開始時（session-start ステップ2）またはコーディング開始・初期化リクエスト時に、カレントディレクトリと最初のユーザー発話を検査:

| ディレクトリ状態と発話 | 判定 | 動作 |
|---|---|---|
| 空 / 設定ファイルのみ（.vscode 等）で、発話にも開発意図が無い | 通常会話 | 何もしない（タグもファイルも作らない） |
| コード・言語マニフェストあり**かつ発話に開発意図がある** | 明らかにコーディング | 自動フロー実行（生成・タグ付け）。AGENTS.md があればタグ付けのみ。タグ確定時は1問だけ確認 |
| マニフェスト等はあるが発話に開発意図が無い | 通常会話 | 何もしない（タグもファイルも作らない） |
| 空ディレクトリだが、発話が新規プロジェクトの作成・初期化を明確に求めている | プロジェクト（予備） | このセッションではタグを作らない（次回セッションで自動タグ付け）。依頼作業自体は通常通り行ってよい |
| 状態が不明 | 不明 | 何もしない（タグを作らない。迷ったら作らない） |

判定は LLM が「cwd のファイル一覧」と「発話の開発意図」の2つを見て行う。初回判定では発話として「最初のユーザー発話」を使い、**両方が開発を示す場合のみタグを作る**。機械的な条件式・ルールファイルは持たない。

**再判定トリガー（cwd が変わった時）**: 初回判定で通常会話と打ち切った後でも、**cwd が変わった時のみ**、その新しい cwd について**1回だけ**再判定する（判定は cwd ごとに1回。同じ cwd では繰り返さない＝暴走防止の上限）。再判定の材料は「新しい cwd のファイル一覧 + ここまでの会話の流れ」の2つ（両方を見る原則は初回判定と同じ）。結果は**4経路**に分岐する: 「**プロジェクト**」→ session-start 2e と同じく make-project を自動起動（手順3の確認1問 → 承認後にタグ確定 → ステップ3復元）。「**プロジェクト（予備）**」→ 初回と同じ規則でタグ無し・次回セッションへ（「このセッションではタグを作らない」は初回・再判定で共通の cwd スコープ規則）。「**タグ済み**」（新 cwd の AGENTS.md の `## プロジェクト識別` 節に `- project: <slug>` 行がある場合のみ。session-start 2a と同一条件）→ make-project を起動せず既存タグを採用してステップ3の復元を実行（タグ既知で変異を伴わないため確認不要。既にあるプロジェクトでは発動しない、と整合）。既存のタグ付き記憶による採用は make-project 手順2 と同一基準に限定（content のパス行の絶対パス一致で自身の記憶と確認できた場合のみ。判別不能なら採用せず「プロジェクト」経路——手順2の重複確認・衝突回避つき——に委ねる）。「**明らかに対象外 / 判定不能**」→ タグを作らず通常会話を継続し、その cwd ではもう再判定しない（cwd が再度変われば新しい cwd について判定する）。再判定で「プロジェクト」と判定した場合のステップ3復元は、**make-project 手順3の承認でタグが確定した後に実行する**（タグ確定前の復元は行わない。ステップ3は冒頭の判定結果に依存して丸ごとスキップされる構造のため、再判定経由では素通りする。復元指示は session-start 側にのみ置く）。

### F2: 自動フロー（判定は自動・変異前に1問確認・事後報告）
- 判定 → slug 決定 → 重複確認は自動で実行する
- 変異（記憶記録・ファイル生成）の直前に、タグ確定の確認を1問だけ取る（slug と概要を示して「`project:<slug>` でタグ付けしていい？」と聞く。判定の確信度は問わず必ず聞く。確認手段は特定ツール名を指定せず、そのハーネスで使える質問手段をエージェントが選ぶ）
- 承認 → 記憶記録・ファイル生成を自動実行し、完了報告（生成したファイル・記録した記憶の一覧）は事後に行う
- 拒否・訂正 → **何も変異させずに中止**（記憶も記録せずファイル生成もしない。取り消しではなく変異前の停止）。slug の訂正だけなら、訂正後の slug で**手順2の重複確認を再実行し**（衝突時は `-2`/`-3` … で回避）、その slug で確認を取り直す
- 確認後に誤りが判明した場合 → 生成物と記憶の取り消しを行う（make-project「誤検知時の取り消し手順」節参照。既存 AGENTS.md に追記した `## プロジェクト識別` 節は**追記分のみ**除去し、既存記述は触らない）
- 既存 AGENTS.md の保護（上書き禁止）は維持する
- git 操作（init / commit / push）は**承認必須**で自動実行しない（make-project 手順 4.7）

### F3: 既存 AGENTS.md 保護
- 既に AGENTS.md が存在する → ファイル全体を生成しない（上書き禁止）
- 既存 AGENTS.md がある場合でも、`## プロジェクト識別` 節（と `- project: <slug>` 行）が無ければ**その節だけを自動で追記**する。slug は AGENTS.md の `## プロジェクト識別` 節から読み取る（節がなければ手順 1 の優先順で決定）

### F4: タグ付け
- 生成時、`memory_create(content="パス: <cwd の絶対パス>。…", tags=["project:<slug>", "project_overview"], importance=0.8, kind="semantic")`。content の先頭にプロジェクトの絶対パスを含める
- slug 衝突時（memory_search で同名検出）→ content のパス行の絶対パスで自身の記憶か別プロジェクトかを判別。別プロジェクトなら slug に `-2`, `-3` … を付与し、**新しい slug で重複確認を再実行**する
- パス行を持たない記憶（パス行導入以前の記録）は「自身」と断定しない。AGENTS.md の `## プロジェクト識別` 節の slug と content の名前が一致する場合のみ自身の記憶とみなし、一致しなければ何もしない（新規タグ付けを保留）
- 既に `project:<slug>` タグ付きの初期記憶が存在する場合はタグ付け済みと判断し、記憶記録をスキップする

### F5: 既存機能との統合
- README / .spec/ / CLAUDE.md / GEMINI.md / .gitignore の生成は従来どおり（既存ファイルは上書きせずスキップ）
- git 初期化と push（手順 4.7）はユーザーの明示的承認が得た場合のみ実行

## 非機能要件

- **配布**: `data/skills/` 配下を更新し、chezmoi externals（`.agents/skills/<name>` = GitHub `solidlime/Nous` main の archive、`refreshPeriod = 1m`）経由で `~/.agents/skills/` に配布する。**push が先、`chezmoi apply -R` が後**（push 前に apply しても何も変わらない）
- **互換性**: 既存 AGENTS.md の復元動作は `## プロジェクト識別` 節の完全一致読取で変わらない。タグ無し・通常会話のセッションでは `project:` タグを使わない挙動を維持（ただし session-start 2c-2 の再判定トリガー——cwd が変わった時の再判定——でプロジェクトと判定し直した場合、または「タグ済み」として既存タグを採用した場合はこの限りではない）。パス行導入以前の `project:` 記憶（実データに存在）はパス判別ができないため、slug 衝突時は「自身」と断定せず、一致しなければ新規タグ付けを保留する
- **ハーネス非依存**: 指示書に特定の質問ツール名を書かない。タグ確定確認はそのハーネスで使える質問手段（質問ツール、対話プロンプト、チャットでの問いかけ）をエージェントが選ぶ。nous ツール（`get_context` / `memory_search` / `memory_create` / `memory_delete`）が直接使えない環境では、MCP ハブ等の仲介経由で「nous」サーバーのツールを探して実行する。**スキル機構を持たないハーネス（Codex 等の AGENTS.md ベース）向けのフォールバックは非スコープ**
- **日本語**: プロジェクト生成物・プロンプトは日本語のまま

## テスト計画

スキルは指示書のためユニットテストなし。実地検証ケース:

1. **空ディレクトリ＋発話に開発意図が無い**: 通常会話としてスキップされること（タグ・ファイルとも作らない）
2. **コードあり＋発話に開発意図あり**: 自動検出 → タグ確定の確認（1問）→ AGENTS.md 生成 + タグ付き記憶が記録されること
3. **コードあり＋発話に開発意図が無い**（調査・質問のみ）: タグもファイルも作らないこと
4. **空ディレクトリ＋発話が初期化を明確に求める**（`cargo init` 等）: 依頼作業は行うが、このセッションではタグを作らないこと
5. **不明 / 判定不能**: タグを作らないこと（迷ったら作らない）
6. **通常会話判定 → cwd 変更 → 再判定でタグ付与**: 初回判定で打ち切った後、cwd が変わった時にその cwd について1回だけ再判定され、「プロジェクト」なら 2e と同じ自動起動（確認1問 → 承認 → タグ付与＋ステップ3復元）が行われること
7. **確認で拒否・訂正 → 何も変異させない（変異前停止）**: タグ確定の確認で拒否・訂正された場合、記憶記録・ファイル生成・タグ付けのいずれも行われないこと（取り消しではなく変異前の停止。確認後に誤りが判明した場合のみ取り消し手順）
8. **slug 訂正 → 訂正後 slug で重複確認再実行**: 確認で slug を訂正された場合、訂正後の slug で手順2の重複確認を再実行し（衝突時は -2/-3 で回避）、その slug で確認を取り直してからタグ付けされること

検証は次セッション以降の実セッションで実施。

## 非スコープ

- opencode プラグイン / nous アプリの変更（しない）
- 機械的な検出ルールファイル（持たない）
- 判定材料の追加（判定材料は cwd のファイル一覧 + 会話の開発意図に固定。初回判定では最初のユーザー発話を、再判定ではここまでの会話の流れを使う）
- スキル機構を持たないハーネス（Codex 等の AGENTS.md ベース）向けのフォールバック（しない）
