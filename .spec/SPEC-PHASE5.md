## P5-1: 神経科学的感情モデル（Mímir 路線）

### 背景

現在の Nous 感情モデルは 22 種類の単一感情 + intensity（0.0〜1.0）。線形減衰のみ。Mímir は 5 神経伝達物質 + PAD（Pleasure-Arousal-Dominance）ベクトル空間でより豊かな感情表現を実現している。

### 構想

| 要素 | 内容 |
|------|------|
| **5 神経伝達物質** | ドーパミン（報酬・動機付け）、セロトニン（気分安定・幸福感）、ノルアドレナリン（覚醒・注意）、アセチルコリン（学習・記憶）、コルチゾール（ストレス反応） |
| **PAD 感情空間** | 3 軸（Pleasure, Arousal, Dominance）で連続的な感情位置を表現。22 離散感情は PAD 空間上の領域としてマッピング |
| **減衰モデル** | 物質の半減期ベースの減衰。環境要因で調整（会話の質→ドーパミン上昇、長時間無応答→セロトニン低下） |
| **状態依存想起** | 気分一致効果（mood-congruent recall）：現在の感情ベクトルに近い感情を持つ記憶を優先検索 |
| **学習** | Hebbian 学習で感情トリガーの連合を強化（「猫」→ joy の経路が太くなる） |

### 前提条件

- [ ] P2-2（感情減衰設定化）完了
- [ ] emotion_history テーブルに persona カラム追加済み
- [ ] 感情伝播（P2-2b）の知見が蓄積されている
- [ ] 複数感情共存の基盤が整っている（P2-2c 完了）

### 参考実装
- Mímir（GitHub TheITVeneran）: 神経化学的感情シミュレーション。約 8,000 行の TypeScript
- mnemos（making-minds.ai）: PAD 空間 + 感情推論エンジン
- EMA（Emotion Model Architecture）: 6 軸感情 + 減衰モデル

## P5-2: マルチユーザーサーバー

### 背景

現在の Nous は localhost 単一ユーザー。Agnai のようなマルチユーザー対応で、キャラクター共有・複数ユーザー同時利用を可能にする。

### 構想

| 機能 | 内容 |
|------|------|
| **ユーザー認証** | OAuth2 / API キー認証。ペルソナ毎のアクセス制御 |
| **キャラクター共有** | ペルソナのエクスポート/インポート。`data/persona/` を zip + config.json |
| **キャラクターマーケットプレイス** | 公開キャラクター登録・検索・ダウンロード。コミュニティ評価システム |
| **マルチテナント DB** | ユーザー毎に persona + session を分離。SQLite → PostgreSQL 移行検討 |
| **Web UI マルチユーザー** | ログイン画面、ユーザー切替、ペルソナ選択 |
| **リソース分離** | ユーザー毎のレートリミット、ストレージクォータ、LLM トークン使用量管理 |

### 前提条件

- [ ] Phase 2〜4 完了
- [ ] アーキテクチャがマルチユーザーを許容する設計に移行している
- [ ] データの暗号化（プライバシー対応）

## P5-3: キャラクター間自律インタラクション

### 背景

OpenCharaAgent 路線。各キャラクターが自律的に行動できるエージェントシステム。

### 構想

| 機能 | 内容 |
|------|------|
| **GM（ゲームマスター）機能** | 特定 persona が「ナレーター」役を担い、シナリオ進行・イベント発生を管理。Phase 4 `narrator_driven` モードの発展形 |
| **イベントシステム** | 時間経過トリガー: 「3 時間経過→空腹」→キャラクターの自律発言「お腹すいた…」 |
| **自律スケジュール** | 各キャラに日課（sleep schedule, work schedule）を設定。時間帯で状態が変化 |
| **自律思考（Idle Think）** | ユーザーがいない間のバックグラウンド思考。DecayWorker の拡張で「このキャラは今何を考えているか」を LLM で生成し memory に保存 |
| **キャラ間関係性進化** | 時間経過や会話内容で `relationship_status` が自律的に変化（「初対面→知人→友人→親友」） |
| **ワークスペース・インベントリ** | 各キャラが固有の作業空間・所持品を持つ。キャラ間でのアイテム受け渡し |

### 前提条件

- [ ] Phase 4（グループチャット）完了
- [ ] バックグラウンドワーカー機構が安定稼働
- [ ] LLM 呼び出しコストの許容（自律思考は定期的な LLM 呼び出しを伴う）

### 参考実装
- OpenCharaAgent: キャラクター自律行動フレームワーク
- SillyTavern: GM 機能の先駆的実装
- Mímir: 状態駆動の自律思考ループ

## 技術的検討事項

### アーキテクチャ進化

```
現在: 単一プロセス Python + SQLite + ComfyUI（画像）
      ↓
Phase 2-3: 拡張パイプライン + CSS/JS UI 強化
      ↓
P5-1: 感情エンジンの独立モジュール化（感情の分離・テスト容易性向上）
      ↓
P5-2: FastAPI マルチテナント化 + PostgreSQL 移行 + Redis セッション管理
      ↓
P5-3: 自律エージェントフレームワーク（各キャラが独立プロセス or async task に近い動き）
```

### DB 移行戦略

| 現状 | P5-2 目標 | 移行方法 |
|------|----------|---------|
| SQLite（ファイルベース） | PostgreSQL | Alembic マイグレーション + データエクスポート |
| 単一データディレクトリ | テナント分離（schema per user） | 段階的移行（読み取りは両対応、書き込みは新DB） |
| ファイルベース画像 | S3 互換ストレージ（MinIO） | 画像 URL をテナントスコープの S3 URL に変換 |
