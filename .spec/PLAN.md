## 🟡 Phase 2: 記憶システム高度化（1〜3週間）

### P2-1: 記憶の階層化（episodic / semantic / procedural）

**背景**: 業界トップは3〜5層の記憶階層。Nous は現状フラットな Key-Value ストア。

**設計**:
```
memory.type ∈ {"episodic", "semantic", "procedural", "reflection", "session_summary"}

episodic:   出来事の記憶（「昨日ラーメンを食べた」）
semantic:   事実・知識（「ユーザーは猫アレルギー」）
procedural: 行動手順・スキル（「コーディング時はCtrl+Enterで送信」）
reflection: 洞察（自動生成、定期的に更新）
session_summary: 会話要約（自動生成、セッション終了時）
```

**実装ステップ**:
1. `memory_type` カラムを `memories` テーブルに追加（enum, default="episodic"）
2. `memory_create` ツールに `type` パラメータ追加
3. `memory_search` に `type` フィルタ追加
4. **記憶統合ワーカー**: エピソード→意味記憶への自動変換（定期的バックグラウンド処理）
   - 複数のエピソード記憶からパターンを抽出
   - LLMを呼び出して「ユーザーはXが好き」のような一般化を生成
   - 元のエピソード記憶は保持（統合≠削除）
5. 想起エンジンの強化: タイプ別の重み付け検索

**学術的基盤**: CAST論文（arXiv 2602.06051）、MNEMA（Zenodo 2026-05）、agent-memory（GitHub）

**期待成果**: 
- 長期記憶の整理・圧縮によるコンテキスト効率の向上
- 意味記憶からの高速な事実想起
- エピソード記憶の詳細な文脈保持

---

### P2-2: 感情モデル高度化

**背景**: Nous の感情モデルは `emotion + intensity + drive` の3要素。OpenHer は5ドライブ + Hebbian学習、Mímir は5神経伝達物質 + 60感情空間。

**段階的改善**:

**Step 1: 感情の持続・減衰（低コスト）**
- 現在の `EmotionDecay` が `emotion_intensity` を時間減衰させているか検証
- 減衰曲線のパラメータを設定可能に（`emotion_decay_rate`, `emotion_decay_floor`）
- 複数感情の共存（`emotions: [{type: "joy", intensity: 0.8}, {type: "curiosity", intensity: 0.3}]`）

**Step 2: 感情伝播（中コスト）**
- 会話中の感情が後続発言に影響: 「怒り」状態では辛辣な表現が増える
- 感情トリガーワード: 特定の話題で感情が変動（「猫」の話題で `joy` 上昇）
- 感情履歴の可視化（`emotion_history` テーブルを活用）

**Step 3: 神経伝達物質モデル（高コスト、将来検討）**
- ドーパミン（報酬・動機）、セロトニン（気分安定）、コルチゾール（ストレス）
- 記憶の符号化・想起への化学的影響
- 参考: Mímir（GitHub）

## 🟢 Phase 3: UI没入・マルチモーダル（2〜4週間）

### P3-1: セルフポートレートのオーバービュー表示

**要件**: 最新の生成画像（self_portrait=true）をオーバービューにステータス風に表示。

**実装**:
1. `image_generate` の `self_portrait=true` 実行時に、生成画像の URL を `persona_state` または専用 `self_portrait_url` フィールドに保存
2. Overview タブに `<img>` 要素を追加: 最新ポートレート + 生成日時
3. 自動更新: SSE で `image_gen_result` 受信時にオーバービュー画像を差し替え
4. 手動更新ボタン: 「最新のポートレートを生成」→ ComfyUI にリクエスト

---

### P3-2: チャット背景・立ち絵

**背景表示**:
1. `persona/config.json` に `chat_background_url` フィールド追加
2. `image_generate` で生成した画像を背景に設定可能に
3. CSS: `.chat-container { background: url(...) center/cover fixed; }`
4. オーバーレイ: テキスト可読性のための半透明レイヤー（`rgba(0,0,0,0.3)`）
5. ぼかし効果オプション（`backdrop-filter: blur(4px)`）

**立ち絵表示**:
1. `persona/config.json` に `character_standee_url` フィールド追加
2. チャット画面の左/右に立ち絵を固定表示
3. 感情連動: 現在の `emotion` に応じて立ち絵を差し替え（`joy.png`, `sad.png` など）
4. CSS アニメーション: ふわっとした揺れ（`idle` アニメーション）
5. クリックで拡大表示（lightbox）

---

### P3-3: 音声入力（Speech-to-Text）

**実装**:
1. Web Speech API（`SpeechRecognition`）を使用したブラウザ内STT
   - 利点: サーバー負荷ゼロ、低レイテンシ
   - 制限: Chrome/Edge のみ、日本語対応済み
2. フォールバック: Whisper API（OpenAI互換エンドポイント経由）
3. UI: マイクボタン（`chat-core.js` に追加）、押下中のみ録音
4. 認識結果をテキストエリアに自動入力 → ユーザーが編集・送信
5. ペルソナの声質設定: `persona/config.json` に `voice_config` 追加（音声入力とは別、TTS用）

---

### P3-4: 画像入力（マルチモーダルチャット）

**実装**:
1. 既存の画像添付機能（`chat-attachments.js`）を拡張
   - 現在: `image_generate` ツール用の参照画像として送信
   - 追加: チャットメッセージとして画像を送信、LLMが画像を認識
2. 画像対応プロバイダ（GPT-4o, Claude 3.5 Sonnet 等）では base64 画像を `content` 配列で送信
3. 画像非対応プロバイダでは自動キャプション生成（別LLM呼び出し）→ テキストとして注入
4. ドラッグ&ドロップ、クリップボード貼り付け対応
5. 自画像固定: アップロードした画像を `self_portrait_url` として保存するオプション

## 🔵 Phase 4: マルチキャラクター・グループチャット（計画のみ）

**背景**: SillyTavern のグループチャットが最も成熟した実装。

**設計概要（実装は Phase 4 以降）**:
1. **セッションモデル**: グループチャット用 `group_session` テーブル
   - `members: [{persona, role}]`
   - `turn_order: "round_robin" | "free_form" | "narrator_driven"`
2. **ターン制御**: 
   - ラウンドロビン: 登録順に発言
   - フリーフォーム: 全キャラが毎ターン発言可能（トークン消費大）
   - ナレーター駆動: GM役のキャラが発言権を割り振り
3. **共有コンテキスト**: 
   - 各キャラの視点から見える情報のみを注入
   - 「AはBの秘密を知らない」→ AのプロンプトにBの秘密を入れない
4. **キャラ間インタラクション**: 
   - キャラ間の関係性（`relationship_status`）が会話に影響
   - キャラAがキャラBに話しかける → 関係性に応じた口調
