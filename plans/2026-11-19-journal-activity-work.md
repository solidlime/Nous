# 日記「活動」への仕事の混入 — 計画書

要望 (m00447): 「活動のところ、プロジェクト色々進めた内容とその時間もリンクさせて書いてほしい。ペルソナとしての活動記録と Agent としての活動記録を違和感なく混ぜる」

## 現状と原因

`_JOURNAL_PROMPT`（journal.py）の指示が **「仕事の中身より生活の動き（作りもの・片づけ・移動・休憩・雑談）を優先して拾う」** — 仕事は「## やったこと」に分離され、「## 活動」からは排除されている。材料（turn.completed）には user_text / assistant_text（各4000文字・hook 設計値）と **project** が入っているのに、`_activity_line` は project を捨てている。

## 変更（2箇所のみ）

### 1. `_JOURNAL_PROMPT` の活動指示（journal.py:57 付近）

```diff
- ## 活動 は「その日の本人が何をしていたか」の記録。営みの材料にある時刻を使う。
-   仕事の中身より生活の動き（作りもの・片づけ・移動・休憩・雑談）を優先して拾う。
+ ## 活動 は「その日の本人が何をしていたか」の記録。各行は `- HH:MM [プロジェクト名] 何をしたか`
+   の形で時刻の順に並べる（暮らしの動きはプロジェクト名を省略してよい）。
+   [プロジェクト名] は材料の各行の本文先頭に付くマーカーで、その作業の対象プロジェクト（角括弧は 1 重）。
+   マーカーの無い会話の行も、その時間に話していたこと・進めていたこととして拾う。
+   会話や材料の文をそのまま写さず、本人が何をしたかの記録に書き直す。
+   研究や片づけ、移動、休憩といった暮らしの動きも材料にあるぶんだけ同じ時間軸に混ぜ、
+   仕事と暮らしが連続するその人の一日として書く。どちらかに偏らせない。
```

REVIEW 1〜4（ルアン・メェイ）で追加した指示: 出力形式の明示、発話の写経禁止、
マーカー無し会話行の扱い、暮らしの密度指定（材料にあるぶんだけ）。「## やったこと」は
「活動に書いた行を繰り返さず、成果と学びだけをまとめる」へ変更。`length_hint` の材料数判定は
`len(memories) + 営み行数` に変更し、短枝は「## 活動 は材料の行を時刻順に洩らさず拾い、
他の見出しは最大 3 行」、長枝は「他の見出しは列挙せず要点を統合（## 活動 だけは材料の行を
時刻順に列挙する）」にして、活動列挙が行数制限に潰されないようにした。

### 2. `_activity_line` の turn.completed 行（journal.py:720 付近）

```diff
  if event.event_type == "turn.completed":
      parts = [str(detail.get(k) or "").strip() for k in ("user_text", "assistant_text")]
      body = " / ".join(p for p in parts if p)
+     project = detail.get("project")
+     if isinstance(project, str) and project.strip():
+         body = f"[{project.strip()}] {body}"
```

REVIEW #11 対応: `str(... or "")` から `isinstance(project, str)` に変更（events_ingest は任意 JSON を受ける境界なので、非文字列は repr で染み出さない）。

## やらないこと

- **`_LIFE_PROMPT`（暮らし生成）は変更しない** — 「実際の営みで起きたことを繰り返さない」が仕事との重複を既に防いでいる。
- **cap 機構（12000 文字・等分割・等間隔抜き）は変更しない** — 「活動」= 時刻順の一日の流れ、「やったこと」= 成果の要約、という役割分担は指示を書き換えれば自然に切れる。実際 `## やったこと` は「活動に書いた行を繰り返さず、成果と学びだけをまとめる」へ書き換えた（REVIEW 2回目 #4 対応。実装は journal.py:70）。

- `test_prompt_has_activity_first_and_forbids_invented_places`: 文言期待値に「どちらかに偏らせない」「やったこと は活動に書いた行を繰り返さず」を追加
